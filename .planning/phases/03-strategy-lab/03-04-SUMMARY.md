## Decisions Made

- **`main(conn=None)` resolves a real connection eagerly.** `get_daily_bars` tolerates `conn=None` by opening its own per-call connection, but `runner.run_backtest`/`ledger.record_run` require a live connection object. `main()` now calls `trader.data.db.get_connection()` once up front (matching `backfill_universe.py`'s precedent) and reuses it for every cell in the run.
- **Fast fixture test loosens `select_top5`'s min-trade floor via monkeypatch, not a code change.** A 45-bar synthetic universe cannot plausibly clear the real 30-trade floor within a sub-5-second test; the test wraps the real `select_top5` with `min_trades=1` via `monkeypatch.setattr`, never touching `sweep.py`'s source or its real production floor.
- **grid_fn injection implemented as a documented, restored, temporary attribute swap on the shared `exit_grid` module** (`sweep.exit_grid.exit_profile_grid = active_grid_fn`, restored in `finally`) — the only way to substitute a tiny grid without editing `sweep.py`'s consume-only `run_tune_sweep`, which calls `exit_grid.exit_profile_grid` directly with no parameter of its own.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `main(conn=None)` crashed on the very first cell of the real acceptance run**
- **Found during:** Task 2 (first real-run attempt)
- **Issue:** `main()` passed `conn=None` straight through to `sweep.run_tune_sweep` -> `runner.run_backtest` -> `ledger.record_run`, which calls `conn.execute(...)` directly. `AttributeError: 'NoneType' object has no attribute 'execute'` on the first cell, before any row was written (confirmed via `backtest_runs` row count unchanged at 52 after the crash).
- **Fix:** Resolve one real `trader.data.db.get_connection()` connection at the top of `main()` when `conn is None`, and reuse it for every `get_daily_bars`/`run_tune_sweep` call in the run — matching `backfill_universe.py`'s established precedent for this phase's real acceptance runs.
- **Files modified:** `trader/backtest/run_tune_sweep_all.py`
- **Verification:** Fast fixture test re-run green (passes an explicit `conn`, unaffected either way); real acceptance run re-launched and completed with the exact expected row-count delta (3600).
- **Committed in:** `f909ca6`

## Issues Encountered

- **The real sweep's wall time (85 min 2 sec) substantially exceeded 03-RESEARCH.md's ~16-30 minute benchmark.** Not a correctness issue — every cell completed, the row-count delta matches exactly, and every candidate verified against the live database. Likely attributable to this machine's characteristics and the stock universe's very long cached histories (several symbols back to the 1960s-1980s, e.g. XOM/DIS to 1962, AMD/JPM to 1980) versus the benchmark's assumptions. Documented here for Plan 03-05's own runtime expectations, not fixed (no bug to fix — an honest, slower-than-hoped real run is not a defect).
- **Only 3 of 12 (strategy, bucket, regime) combinations produced any candidates at all** (all momentum: `crypto_major_legacy_meme`/trending, `stock`/choppy, `stock`/trending — 5 candidates each, 15 total). Breakout never cleared the 30-trade floor in any bucket/regime, and momentum missed the floor in `crypto_major_legacy_meme`/bear and both `new_memecoin` regimes. This is D-10's honest floor working exactly as designed — `select_top5` returns `[]` for a combo with zero eligible cells rather than padding or erroring — not a bug. Flagged here explicitly for Plan 03-05, whose OOS validation input is correspondingly narrower than the full 12-combo grid.
