# Phase 6 — Plan 06-01: Graduation Checklist Evaluator

**Planned:** 2026-07-29
**Covers:** the BUILD half of Phase 6 (the runtime half is 1–3 months of
unattended paper trading, blocked on the 05-08 ops checkpoint).
**Depends on:** Phase 7 complete (tournament judge, attribution dashboards).

## Objective

A mechanical evaluator for the five pre-registered graduation checks, frozen
behind a hash gate, run weekly after the tournament in the same scheduled
invocation, producing an advisory report the owner graduates from — never an
automated state change (D-07).

## Wave 1 — Frozen checklist + migration

### Task 1.1: `trader/graduation/frozen_checklist.py` + gate
- Constants (phase doc verbatim): `MIN_TRADES_FOR_GRADUATION=50`,
  `PF_GRADUATION_FLOOR=1.3`, `MAX_DD_GRADUATION=-0.15`,
  `MIN_PROFITABLE_CONDITIONS=2`, `MAX_SINGLE_TRADE_PROFIT_SHARE=0.40`,
  `ADVERSE_FILL_PCT=0.01`.
- Hash gate mirrors `trader/tournament/freeze_gate.py` exactly (fourth
  independent gate, per the v1→v2→tournament precedent).

### Task 1.2: Migration `0007_graduation.sql`
- `graduation_reviews` (append-only): review_id, ts, profile_name,
  trade_count, check results (one column per check: pass/fail/value),
  overall_pass, checklist_hash, report_path.

## Wave 2 — Evaluator + checks

### Task 2.1: `trader/graduation/evaluator.py`
- `evaluate_strategy(conn, profile_name, now)` → dict with the five checks:
  1. PF from `metrics.compute_metrics` over ALL closed trades (≥50 required
     first — else verdict `not_enough_trades`, no checks run).
  2. Max DD from the same metrics call (daily equity curve).
  3. Regime buckets per D-03 (frozen regimes_v2 windows by exit date; SPY
     50-day-mean fallback, pre-registered).
  4. `max(trade pnl) / total profit <= 0.40` (only when total profit > 0).
  5. Adverse-fill recompute per D-04: entry×1.01, exit×0.99, fees unchanged.
- `run_graduation_review(conn, now, report_base_dir)` → evaluates every
  active strategy, appends `graduation_reviews` rows, writes the markdown
  section, returns a summary. Verdicts are advisory (D-07).

### Task 2.2: Wire into `run_tournament.py`
- After the tournament run + dashboard regeneration, call
  `run_graduation_review` (same never-fail try/except pattern as the daily
  report's dashboard block). One scheduled task total (D-05).

## Wave 3 — Runtime gate documentation
- STATE.md tracks the runtime clock: starts when 05-08 closes and the entry
  pipeline submits its first live-paper order; 3-month iterate-in-Phase-3
