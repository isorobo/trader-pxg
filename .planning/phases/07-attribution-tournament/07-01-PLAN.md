# Phase 7 — Plan 07-01: Registry Substrate, Config Store, Probation Sizing

**Planned:** 2026-07-28
**Covers:** ATTR-04 substrate, D-02, D-04 (sizing half), D-06, D-08
**Depends on:** Phase 5 complete (511 tests green). Research: 07-RESEARCH.md (all call sites verified).

## Objective

Move the live strategy roster from the hardcoded `config.LIVE_STRATEGY_CONFIGS`
tuple into a DB-backed `strategy_registry`, so tournament decisions take effect
at the next entry-pipeline run without code edits (D-08). Freeze the tournament
thresholds behind a hash gate (D-06). Apply 25% probation sizing at the one
correct insertion point (D-04).

## Bug fix folded in (identity mismatch)

`guardian.evaluate_kill_conditions` keys `is_strategy_retired` /
`get_recent_trades` / `retire_strategy` on `cfg.strategy_id`
("momentum_stock", shared by all five configs). Trades and positions are keyed
by `profile_name` (`entry_pipeline` passes `profile_name` to `open_position`;
`close_position` copies it into `paper_trades.strategy_id`). The kill query
therefore always returns zero trades and no kill condition can ever trip.
Wave 2 re-keys the guardian loop on `cfg.profile_name` and updates
`tests/test_guardian.py`'s kill-condition tests to seed trades under a real
profile_name. This corrects the plumbing only — no threshold changes
(standing rule 1 untouched).

### Task 2.2: Probation sizing (D-04)
- Reorder the STEP 4/5 per-position loop: resolve `profile_name`/`cfg` first,
  then `dollar_amount = weight * PAPER_ACCOUNT_EQUITY * multiplier` where
  `multiplier = PROBATION_SIZE_MULTIPLIER if cfg.state == 'probation' else 1.0`.
- Heal paths (STEP 0, STEP 1) never apply the multiplier — they reconstruct an
  already-placed order's qty verbatim (research Pitfall 3).
