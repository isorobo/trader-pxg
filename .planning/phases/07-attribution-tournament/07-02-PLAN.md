## Wave 3 — `trader/tournament/pipeline.py` (D-07 state machine, ATTR-03)

One transition function owns every state change: it UPDATEs
`strategy_registry.state` and appends a `strategy_registry_transitions` row in
the same transaction — never a bare UPDATE (research security table, silent
state drift). `retired` is terminal: any transition attempt raises.

- `register_candidate(conn, ...)` → INSERT state='candidate' + transition row.
- `stamp_backtest(conn, profile_name, run_id)` / `stamp_oos(conn, profile_name, ref)`
  — evidence stamps, write-once.
- `promote_to_probation(conn, profile_name, now)` — raises `MissingEvidence`
  unless both backtest and OOS stamps are present; raises `CapExceeded` when
  active (probation+full) count ≥ 6 or quarter's entrants ≥ 2 (calendar
  quarter of `now`, counted from transitions to_state='probation'). Queued
  candidates simply stay 'candidate' (D-05).
- `confirm_paper_30(conn, profile_name, now)` — stamps `paper_30_confirmed_at`
  once ≥30 closed `paper_trades` rows exist for the profile.
- `promote_to_full(conn, profile_name, sharpe, now, run_id)` — requires
  state='probation', the paper-30 stamp, and sharpe ≥ frozen promotion floor.
- `retire(conn, profile_name, reason, trigger_value, now, run_id)` — registry
  transition + `ledger.retire_strategy(conn, profile_name, 'tournament_demotion', ...)`
  (D-08's "retire also triggers the existing kill path").

The `Strategys/` library files 10–12 (Donchian, RSI-2, TS-momentum) are the
intended first `register_candidate` entrants once Phase 8 builds their signal
code; this phase ships the pipeline they will enter through, not their signals
(CONTEXT.md deferred: human-approved entrants only).

## Wave 4 — `trader/tournament/judge.py` + `run_tournament.py` (ATTR-02, D-03/D-09)

`run_tournament_once(conn, now=None)`:
1. `verify_frozen_tournament()` — hard gate before anything else.
2. Registry hash before (sha256 over sorted `profile_name:state` pairs).
3. Insert `tournament_runs` row (hash_after filled by UPDATE at the end).
4. Per active strategy: trades = `ledger.get_recent_trades(conn, name, 30)`;
   metrics = `metrics.compute_metrics(trades, starting_equity=config.PAPER_ACCOUNT_EQUITY)`
   — reused unmodified, same fixed base for every strategy (research Pitfall 4).
5. Decisions, each with a `rule_citation` string quoting the numbers:
   - <30 trades → `hold` (D-03 eligibility).
   - probation, ≥30, sharpe ≥ promotion floor → `promote` (stamps paper-30
     first if needed).
   - full: rank by sharpe, PF tie-break. Worst-ranked AND sharpe < demotion
     floor → `demotion_strike=1`; K=4 consecutive strikes (from prior runs'
     decisions) → `retire` via `pipeline.retire`. Compound rule — never rank
     alone (research Pitfall 5).
   - candidates with full evidence → `enter` (promote_to_probation) when caps
     allow; `hold` (queued) otherwise.
6. Registry hash after; UPDATE run row; write markdown decision record to
   `reports/tournament/{YYYY-MM-DD}-run{run_id}.md`; `alerts.notify` summary.

`run_tournament.py`: `python -m trader.tournament.run_tournament --once`
(argparse shape mirrors entry_pipeline), also regenerates the dashboard.

**Verify:** `tests/test_tournament.py` (eligibility, promotion, tie-break,
strike sustain, healthy-roster-never-empties, caps) +
`tests/test_tournament_audit.py` (citation completeness, hashes set,
retire-path IntegrityError regression, Telegram called once).
