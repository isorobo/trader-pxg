<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External API responses (Yahoo Finance, CoinGecko) -> local parsing | Third-party, unauthenticated-by-us response data enters the process |
| Ticker/coin-id strings -> SQL statements | Values derived from external API responses reach `INSERT`/`SELECT` statements |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-00-03 | Tampering | `trader/ground_truth/db.py` `insert_snapshot_rows` | mitigate | Parameterized `?` placeholders only, never string-formatted SQL, even though tickers are not directly user-supplied — a malformed API response should never be able to inject SQL |
| T-00-04 | Tampering | `trader/ground_truth/sources.py` normalization functions | mitigate | Validate expected fields exist and are the expected type before returning a row; a malformed/unexpected response is logged and skipped, not partially inserted |
| T-00-05 | Information Disclosure | `trader/ground_truth/sources.py` CoinGecko client | mitigate | Failure logs never print the `x-cg-demo-api-key` header value or the full request object — exception type/message only |
</threat_model>
